# Dynamic Model Routing CLI Pilot Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for serial implementation, with independent read-only platform checks and final review. The workspace has no Git repository; do not initialize one or make commits. Keep the existing Handoff.md as the progress record.

The implementation plan completed under those original constraints. On 2026-09-12, the user subsequently authorized initializing Git and publishing the reviewed pilot as a public MIT-licensed repository under `iumi-in`.

**Goal:** Deliver a self-contained, usable native routing plugin for a Codex CLI and Claude Code CLI pilot.

**Architecture:** One canonical skill classifies risk and delegates through native host tools. Two references describe actual host capabilities and setup. JSON manifests expose the same skill to both clients; Python validates the package without becoming a plugin runtime dependency.

**Tech Stack:** Markdown, JSON, YAML-compatible metadata, Python 3.11+ standard library for offline validation; installed Codex and Claude Code CLIs for native checks.

**Spec:** `docs/superpowers/specs/2026-09-12-dynamic-model-routing-design.md`, approved pilot amendment.

## Global Constraints

- Initial targets: Codex CLI and Claude Code CLI only; Cursor and desktop integration deferred.
- Preserve Advise/Apply/Configure, four routes, risk floors, explicit choices, execution holds, bounded attempts, independent review, and truthful usage.
- No proxy, fixed model ranking, telemetry service, new runtime dependency, global settings changes, credential access, commit, or publication.
- Keep the installed user foundation unchanged; distribute no personal absolute paths.
- Requested routing, loaded configuration, effective execution, and measured savings are separate evidence levels.
- Root serializes all writes; research and review agents are read-only. Use native temporary loading if supported; do not weaken sandbox, approval, or trust boundaries.
