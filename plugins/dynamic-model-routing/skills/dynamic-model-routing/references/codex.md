# Codex CLI adapter

Use this reference with the shared skill. Resolve capabilities once per session; refresh after a failure or configuration change. The pilot packages instructions, not permanently ranked worker definitions.

## Discover and dispatch

Inspect exposed model metadata and native delegation tools first. On a CLI, inspect `codex --help` and `codex debug --help`; use a catalog command only if installed help lists it. `codex debug models --bundled` supplies identifier/effort metadata on the author's checked client. It does not prove account access, runtime identity, or relative quality.

Choose the lowest adequate eligible model for the route and a supported effort. Use the current session's native worker tool with an explicit pair when its schema permits. Include task boundaries, owned files, acceptance checks, original constraints, failed attempts, and no recursive delegation. Review workers are read-only. Remain local for small work when the coordinator is adequate and dispatch overhead would dominate.

Custom role settings can override explicit spawn values. Check relevant existing role fields before choosing a role; avoid a conflicting role or make an authorized project update. Do not report the supplied arguments as the effective model. If the tool lacks model selection, state the limitation; a new shell process is not an automatic substitute for native delegation.

## Configure only when requested

Read the project's instructions and complete existing changes. Prefer one routing section in an existing project-owned document. Do not edit a reusable AGENTS.md template just to activate this skill. Record dated role bindings, evidence, acceptance requirements, holds, and rollback.

Only create native roles when direct dispatch is insufficient or persistent roles are useful. Verify the installed schema before writing `.codex/config.toml` or `.codex/agents/*.toml`. Give pinned roles both model and effort when supported. Preserve existing keys, instruction precedence, permissions, trust, network, authentication, and service tier. Do not replace `developer_instructions` or enable additional permissions. Four policy routes do not require four worker files.

## Verify and recover

Parse changed configuration, then inspect native loaded values if the client exposes them. Saved files are not evidence of loaded settings; loaded settings are not proof of execution. Existing sessions may require a reload. Record native dispatch ID and effective model/effort only when supported runtime evidence exposes them; otherwise write `unavailable`.

If a model is unavailable, preserve explicit pins and capability floors. A permitted alternative still needs an eligible binding. Missing access or unsupported tools are prerequisite failures, not evidence that more reasoning will help. Apply the shared bounded-escalation rule only to concrete failed work.

Plugin removal does not reverse project configuration created by Configure. Its completion report must list those separate edits and how to restore them without losing later changes.
